# 支線任務目的地與方向導航規格

> 狀態：v0.53.1 已實作導航初版；精確敵將座標與部分地圖內路徑仍需逐張地圖校正。
> 適用：所有章節的支線任務、支線 NPC、探索型支線與多階段支線。

## 一、核心要求
每條支線都必須讓玩家知道「要去哪裡、往哪個方向走、到哪個位置找誰／做什麼」。不可只寫模糊任務文字，讓玩家盲目探索。

## 二、任務追蹤欄
支線啟動後，顯示任務名稱、目的、目前階段／目標、目的地名稱與區域、方向提示、地圖位置、目的地類型、目標 NPC／敵人／物件、完成條件與下一步目的地。若線索尚未揭露秘密位置，只顯示已知線索與下一個可調查來源，不直接洩漏隱藏地點。

## 三、大地圖與區域地圖指引
- 固定目的地在大地圖以支線任務標記顯示，與主線標記區分。
- 城內、洞穴或多層地圖需標示正確入口／樓層／區域，不只標到整座城。
- 尚未解鎖或尚不可抵達時，顯示方向、最近可抵達入口／關口及解鎖條件。
- 迷宮／洞穴指引入口、樓層、分岔方向或地標。
- 標記不得遮住重要地形、NPC 或互動物件。
- 任務位置因旗標或目標移動而變化時，任務文字與標記同步更新。

## 四、多階段支線
- 每個階段都有獨立目標與目的地。
- 完成一步後立即更新任務追蹤、方向與地圖標記。
- 找人、調查、戰鬥、取得物品、交付與回報等步驟依序列出。
- 完成、失敗、暫停或因章節封鎖無法進行時，顯示狀態與原因。
- 交付物品時標示交付對象與地點。

## 五、方向文字範例
- 「從陳留城南門出城，沿主路向東北方前往東阿。」
- 「抵達東阿後，前往城外東側山道，尋找受傷的斥候。」
- 「斥候交付線索後，目的地更新為泰山寨入口；進入寨內後往北側營地調查。」
- 「完成戰鬥後返回東阿城內，向 NPC 李老兵回報。」
以上僅為格式示例；實際方向、地名、NPC 與路線須依遊戲地圖資料確認，不可照抄成不存在的路線。

## 六、任務資料欄位建議
每個支線階段至少需有 questId、stageId、title、description、objective、destinationMapId、destinationLocationId 或 destinationCoordinates、destinationType、destinationName、targetNpcId／targetEnemyId／targetObjectId（適用時）、directionHint、landmarkHint、entryId／floorId（適用時）、unlockRequirements、completionConditions、nextStageId、mapMarkerType、visibilityCondition、questStatus。欄位名稱依現有 schema 調整，先盤點既有資料，避免重複或破壞存檔相容。

## 七、驗收清單
- [ ] 每條支線接取後可看到目前目標與目的地。
- [ ] 有方向文字，不只顯示地名。
- [ ] 大地圖可定位；城內／洞穴／多層任務標示正確入口或樓層。
- [ ] 多階段支線每一步更新下一個位置。
- [ ] 未解鎖地點顯示前置條件與最近可抵達路線。
- [ ] 隱藏位置在取得線索前不直接揭露。
- [ ] 地圖標記、任務文字與任務旗標同步。
- [ ] 導航不遮擋地圖操作，不改變戰鬥／劇情流程。
- [ ] 舊支線資料與存檔相容。

## 八、開發狀態
本文件是需求規格，尚未修改支線任務資料、地圖標記或遊戲程式。實作前先盤點現有支線與地圖節點，再逐批補齊目的地、方向和階段導航。
